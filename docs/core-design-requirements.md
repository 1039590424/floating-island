# 个人工作站 · 核心设计要求

## 项目定位

这不是一个传统意义的个人主页,而是一个**个人工作站**——同时承担两个身份:

- **对外**:展示个人资料、技能与作品成果,让别人快速了解"我是谁、能做什么"
- **对内**:作为日常工作中的实用工具集合,自己高频打开、即开即用

核心原则是**实用优先**。所有"有意思的设计"都建立在好用的基础上,是锦上添花,不是主体。网站不追求炫技,而是追求在每一次打开时都能真正帮上忙,同时让人会心一笑。

### 展示优先,工具按需拉出

网站默认呈现的是**别人能看到、或者你想让别人看到的内容**。访客打开链接,第一眼看到的是展示页——关于你、你的技能、你的作品。这符合访客的预期:他们点开链接是想了解你,不是想看你干活。

工具区(快捷工具、知识库、任务日程、AI 任务)和个人项目工作区不默认展示,而是通过**侧边栏或开关**拉出。访客可以正常浏览展示内容;自己使用时拉出侧边栏,切换到工具模式。这样做的好处是:

- 访客不会被一堆工具界面干扰,看到的是干净的个人展示
- 自己使用时一键拉出工具区,不影响日常效率
- 一个站点、两种模式,通过侧边栏切换,而不是做成两个独立页面

交互上要符合用户习惯:侧边栏的展开/收起方式、入口位置、切换动效都应该直觉化,不需要学习成本。

## 部署与隐私

网站将部署在 GitHub Pages 上,任何人都可以通过公开链接访问。这带来一条硬性约束:

**公开展示的内容中不得包含敏感个人信息。** 具体来说:

- 不展示真实电话号码、身份证号、家庭住址等隐私数据
- 邮箱、社交账号等联系方式以可控方式呈现(如通过中间表单或脱敏处理)
- 任务、日程、知识库等"对内工具"模块的数据存储在浏览器本地(localStorage),不上传服务器,不随仓库公开
- 仓库代码中只包含结构与样式,不硬编码任何个人敏感数据

可以公开展示的内容包括:网站功能本身、个人简介与经历、技能概览、作品与项目案例、个人感悟卡片。这些内容会随项目推进逐步填充。

## 模块规划

基于"展示优先,工具按需拉出"的架构,工作站分为两层:默认可见的**展示层**和需要拉出的**工具层**。

### 展示层(默认可见)

访客打开链接第一眼看到的内容。这是站点的默认视图,承载"让别人了解你"的职能。

**关于我** — 个人简介、职业经历、联系方式(脱敏)。让别人用最短时间了解你的背景。

**技能矩阵** — 技能分类与熟练度展示,可以加入成长时间线,让技能不只是标签,而是有故事的可视化。

**项目成果集** — 作品与案例的集合。每个项目包含背景、角色、成果与反思,而不是干巴巴的截图堆砌。

**感悟卡片** — 带有游戏化色彩的模块。将日常感悟、思考片段制作成卡片,引入**抽卡机制**——访客和自己都可以抽取一张感悟卡片。抽卡本身有仪式感和随机性,卡片可以收藏、回看。这是展示层中唯一带强交互的模块,既是个人审美的窗口,也是游戏化体验的载体。放在展示层是因为它对外可见、有趣味性,能给别人留下印象。

### 工具层(侧边栏拉出)

通过左侧边栏或开关展开的区域,不默认展示。主要服务自己的日常使用,访客也可以访问但不是默认焦点。

**工作台 Dashboard** — 拉出侧边栏后的默认工具页。一个可用的工作概览——快速入口、最近动态、常用工具直达。它的角色是工具层的分发枢纽,把使用者引导到具体工具。

**快捷工具集** — 日常高频使用的小工具:格式转换、计算器、编码解码、文本处理等。即用即走,不设多余步骤。

**知识库** — 个人笔记、书签收藏、资源整理。方便自己随时查阅和补充。

**任务与日程** — 待办事项、计划安排、时间线追踪。数据本地存储,不上传。

### 侧边栏交互

侧边栏是连接展示层与工具层的核心控件,需要做到:

- 入口明显但不抢眼,访客一眼就知道有更多内容可探索,但不会被干扰
- 展开/收起的操作直觉化(如边缘把手、汉堡按钮、快捷键),符合常见 Web 应用习惯
- 展开时展示工具层各模块的导航入口,收起后回到纯展示视图
- 切换过程有流畅的过渡动效,不突兀

## 视觉与交互设计方向

### 任天堂游戏风格

整体视觉调性参考任天堂游戏的设计语言:明快、友好、有温度。不追求极简主义那种冷峻的留白,也不做花哨的堆砌。具体特征:

- **色彩**:明快但不刺眼,有辨识度的主色调搭配柔和的辅助色,支持多套配色切换
- **形状**:圆润的边角、有亲和力的图标,避免尖锐冷硬的几何感
- **质感**:轻盈但不轻浮,元素有恰到好处的层次感(轻微阴影、柔和过渡),不追求拟物化的厚重
- **字体**:清晰易读为主,标题可以有性格,正文保持克制

### 灵活与多风格

"灵活一点,多风格一点"意味着工作站不是从头到尾一种调性走到底。不同模块可以有微妙的风格差异——工具区更干脆利落,展示区更从容舒展,感悟卡片区更有游戏感。但所有风格变化都共享同一套底层设计语言(色彩体系、字体规范、间距节奏),保持整体一致性。

极简的内核是指:底层逻辑简单、信息层级清晰、操作路径直接。不被丰富的视觉表现干扰使用效率。

### 展示层与工具层的视觉区分

两层在视觉上有微妙但可感知的差异,帮助用户直觉地知道自己处于哪个模式:

- **展示层**:从容舒展,以阅读体验为先,留白更多,信息呈现有节奏感
- **工具层**:干脆利落,以操作效率为先,信息密度更高,控件更紧凑
- 侧边栏展开时,可以用背景色或氛围的轻微变化暗示模式切换,但不做剧烈的整体风格跳变

### 游戏化交互

在实用的基础上,用游戏化的方式让日常操作变得有趣:

- **抽卡机制**:感悟卡片模块的核心交互,有抽取动画、稀有度区分、收藏图鉴
- **任务执行特效**:当用户(或 AI)在执行任务时,有"正在干活"的动作特效——可以理解为一个角色在工作站里忙碌的小动画,让等待过程不枯燥
- **即时机反馈**:每次操作都有轻盈的视觉或动效反馈(按钮按下、任务完成、卡片翻转),但不滥用动效,不影响操作流畅度
- **彩蛋与惊喜**:在不起眼的角落藏一些小彩蛋,让长期使用的人偶尔发现会心一笑

### AI 任务发布

工作站支持发布让 AI 执行的任务。用户在工作站里描述一个任务,AI 接收后开始执行,执行过程中有"干活中"的视觉反馈(角色动画 + 进度指示),完成后呈现结果。这个功能让工作站不只是一个静态展示页,而是一个能真正帮你做事的助手界面。

## 技术约束

- **纯前端**:HTML + CSS + JavaScript,无需后端服务器,数据存浏览器本地
- **部署**:GitHub Pages,静态文件直接托管
- **依赖**:尽量轻量,优先用原生能力,按需引入库
- **离线可用**:核心功能在无网络环境下也能使用
- **响应式**:适配桌面端为主,移动端基本可用

## 开发节奏

项目采用**逐步迭代**的方式推进,不追求一次成型:

1. 先搭框架与目录结构(当前阶段)
2. 逐个模块实现基础功能
3. 在功能可用的基础上叠加游戏化交互与视觉打磨
4. 持续填充个人内容,调整细节

每一步都以"可用"为验收标准,而不是"完整"。先让骨架跑起来,再往里填血肉。
